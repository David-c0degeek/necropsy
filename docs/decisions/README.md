# Architecture decisions

[Documentation](../README.md) · [Current architecture](../architecture.md)

These accepted decisions describe implemented contracts and their consequences.
They describe design boundaries; actual authenticated Windows validation is
recorded separately in [observed live validation](../live-validation.md). The confidential-client design is for personal use.

| Decision | Contract |
|---|---|
| [Personal authentication](0001-personal-authentication.md) | One approved OS credential store; public-client PKCE required before distribution |
| [Bounded acquisition and fair cohorts](0002-bounded-acquisition.md) | Fixed endpoint, explicit context, graded faction and bounded comparison samples |
| [Immutable revision generations](0003-immutable-generations.md) | No-clobber cache, verified completion and whole-entry restarts |
| [Snapshots and derived outputs](0004-snapshots-and-derived-outputs.md) | Strict live archive, shared offline pipeline, rebuildable database and explicit output replacement |

| [Classes and encounter duties](0005-class-and-encounter-duties.md) | Separate class/build/category/duty/override evidence and compatible class sections |

| [Shared class combat evidence](0006-shared-class-combat-evidence.md) | Verified ranking categories, common combat plugins and shared execution views |

| [Public-client PKCE](0007-public-client-authentication.md) | Separate tagged modes, secret-free user endpoint, installed verification and explicit live release gates |

| [Resumable acquisition and current installs](0008-analysis-resume.md) | Saved requests, owned-output checks, quota recovery and versioned design verification |

| [Guided terminal and installation](0009-guided-terminal-and-installation.md) | TUI lifecycle, saved-run library, quota supervisor and private bootstrap runtime |

| [Graphical desktop](0010-graphical-desktop.md) | Tauri shell, allowlisted process bridge, shared analysis service, sandboxed reports and independent desktop verification |

| [GUI-first installation](0011-gui-default-installation.md) | Native default launch, staged GUI/CLI upgrades, per-OS bootstrap checks and publish-before-switch release ordering |

| [Game builds and WCL categories](0012-game-build-and-wcl-category.md) | Separate declared trees, observed build totals, ranking pools, duties and race validity; compatible saved evidence |
| [Saved report and app updates](0013-saved-report-and-app-updates.md) | Preserve saved analysis ownership during refresh; explicit verified releases through staged installers and safe restart |
| [Recipient-qualified healing](0014-recipient-qualified-healing.md) | Separate friendly support, boss mechanics and unresolved recipients while preserving raw source totals and historical Naxx arithmetic |
| [Encounter observations and strategy](0015-encounter-observations-and-strategy.md) | Keep sourced general strategy, observed actor effects, unknown phase/opportunity and personal assignments separate in the shared pipeline |

| [Encounter event scope](0016-encounter-event-scope.md) | Separate actorless encounter/critical coverage, explicit live format2, shared normalization and preserved historical/v1 defaults |

| [Target instance aura observations](0017-target-instance-aura-windows.md) | Exact NPC instances, scoped encounter coverage and observed buff states separate from phases and personal opportunities |
| [Owned summon healing](0018-owned-summon-healing.md) | Individual owned-unit friendly support, strict event integrity and separate actor/ranking evidence |
| [Raid interruption context](0019-raid-interruption-context.md) | Deduplicated raid-member effects with named sources, qualified NPC instances and separate player credit |
