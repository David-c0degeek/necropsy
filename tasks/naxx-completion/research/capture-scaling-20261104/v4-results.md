# Whole-fight projections: implementation result

The follow-up implementation enables derived source/critical views by default for Naxxramas encounter-context captures. Physical encounter-All cache identity remains class-independent. Required top-ranked same-faction subjects and comparisons are still selected separately; arbitrary raid participants are not promoted into eligible comparisons.

## Capture and proof contract

- Acquire the complete encounter-All scope first. Prefer an existing verified requested source/critical scope; cache corruption remains an error. Otherwise derive supported views without those API requests.
- Actor-source includes every event whose sourceID or targetID belongs to the actor or a transitively owned report-catalog/fight unit. Incomplete ownership retains requested source streams. Catalog conflicts, cycles, missing identities and malformed ownership refuse projection.
- Critical damage selects hit types 2, 5 and 17. All damage events must have an integer hit type from the rule's explicit known domain; otherwise request the original critical scope. Real captures established Environment actor -1 as an unowned sentinel and damage hit type 15 as non-critical. Regression tests retain both witnesses.
- Preserve order, duplicate events, empty pages and the full parent's cursor chain. Generated child pages are materialized archive members, not fabricated API answers. They carry neither a request identity nor request costs.
- Snapshot format 4 names the exact parent request and every parent page hash. The strict reader rechecks parent scope/completeness and compares the exact generated bytes, even when a forged child is rehashed. Source ownership binds to the original acquisition's separately hashed report, not merely its final combined report.
- Existing v1/v2/v3 archives remain readable. Cache-first resumes can still emit v3 when all source/critical scopes already exist as requested data. No old cache page or registered archive was rewritten.
- Raw actor/encounter oracles, DPS/HPS freezer paths and queue/archive validators support v4. The raw projection verifier is independent of the runtime projector and reader.

## Measurements and their limits

The four-fight synthetic capture with player and pet scopes makes **8 event-page requests instead of 32**, preserving the original independent actor/encounter arithmetic. This is a 75% event-request reduction for that fixture. The prior seven-archive audit found 964 potentially removable source/critical pages of 1,963 event pages (49.1%); conservative guards and cache state can reduce the realized saving. Neither number measures WCL's billed point savings or live throughput.

Six unchanged hash-pinned registered archives exercise equivalence against recorded API source/critical streams, including the catalog-only ownership counterexamples. One entire archived capture is converted only inside a temporary test fixture and read with both native and independent verification; original stream events, order, multiplicity, status and boundary ambiguity remain equal. This constructed fixture is not accepted content evidence. Test inputs are pinned in `tests/golden/raids/projection-corpus.json`, independently of this research directory.

## Compatibility and rollout

An sdist and wheel were built locally, with the wheel built from the sdist. The wheel was installed into an isolated environment and imported from site-packages with Python isolated mode. It read a new v4 fixture and generated offline analysis, HTML report, playbook and export package. The artifacts retain the checkout's development version 0.7.1 and are private verification builds, not a release.

Released 0.7.1 readers refuse v4. Updated consumers must accompany rollout of a v4 producer. At the initial implementation-verification cutoff, production had not changed and no WCL event queries, additional accounts or new credentials had been used for that validation. The owner subsequently explicitly requested deployment: the verified private image was deployed at 21:33 UTC and its new waiting heartbeat verified at 21:34 UTC. See [deployment.json](deployment.json) and the Tower maintenance record `changes/2026-11-04-necropsy-projections-rollout.md`. The active image contains both producer and updated reader; this is not a public release. Live budget/elapsed-time validation awaits the existing scheduled quota reset.
